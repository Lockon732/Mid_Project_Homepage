Tantangan Membangun Bot Vision-Based menggunakan PyAutoGUI

Dalam pengembangan proyek Autostepper, salah satu kendala terbesar adalah memastikan tingkat akurasi pemindaian layar (screen parsing). Bot berbasis computer vision harus murni mengandalkan template matching dan analisis piksel — berbeda dengan injeksi memori atau intersepsi paket jaringan.

1. Anomali Subpixel Anti-Aliasing (ClearType)

Bot gagal mengenali tombol antarmuka yang tampak identik secara kasat mata. Setelah membedah piksel tangkapan layar, saya menemukan bahwa teks "putih" sebenarnya tidak murni putih. Sistem operasi menggunakan Subpixel Anti-Aliasing untuk memperhalus ujung teks, menghasilkan pinggiran seperti (232, 200, 162) (persik) atau (178, 210, 238) (biru muda).

Solusinya elegan: menyuntikkan parameter grayscale=True ke modul penglihatan bot. Ini melucuti semua data warna dan memaksa bot hanya mengevaluasi bentuk hitam-putih, menetralisir efek anti-aliasing sepenuhnya.

2. Inkonsistensi UI dan CSS :hover State

Pengembang web sering menggunakan pseudo-class :hover pada CSS. Saat kursor berada di atas tombol, warnanya berubah terang — namun karena bot memindahkan kursor menjauh saat jeda, ia selalu melihat tombol dalam resting state yang gelap. Akibatnya, bot keliru mengklik elemen yang sudah habis karena warnanya serupa.

3. Rekayasa "Luminosity Scanner"

Daripada mencari kode RGB tertentu, saya merancang Luminosity Scanner yang memindai garis horizontal melintasi tengah tombol untuk mencari piksel dengan kecerahan tertinggi. Dengan ambang batas 160, bot kini dapat mengabaikan tombol mati dan mengekstraksi sumber daya dengan akurasi 100%.

4. Manajemen State dan "Dead Reckoning"

Memindai UI terus-menerus sangat tidak efisien. Karena setiap poin energi membutuhkan 5 menit untuk beregenerasi, saya mengimplementasikan Dead Reckoning: ketika energi habis, bot menyetel kronometer internal 80 menit, lalu secara otonom beralih ke mode arena tepat saat waktu habis.

Kesimpulan

Membangun bot bukan sekadar merekam klik mouse. Ini tentang membangun State Machine yang tangguh. Dengan arsitektur Object-Oriented yang mendefinisikan BotState dan kelas Config sentral, proyek ini berevolusi dari skrip sederhana menjadi entitas automasi yang sepenuhnya mandiri.

Pergeseran Paradigma Menuju Mythical Immortal: Mengapa Draft Memegang 60% Kemenangan

Setelah menembus 100 bintang dan mengamankan rank Mythical Immortal dengan win rate 62.5% dalam 272 pertandingan, sebuah realitas sistematis menjadi sangat jelas. Sistem kompetitif di tingkat ini — dihuni kurang dari 1% total pemain — beroperasi dengan aturan main yang sama sekali berbeda.

1. Supremasi Mikro di Bawah Immortal

Di rank bawah hingga awal Mythic, dominasi sangat ditentukan kemampuan Mikro Hero. Penguasaan mekanik superior — kecepatan tangan, akurasi, refleks — bisa membawa tim menang secara sepihak. Namun memasuki Immortal, mekanik tinggi berhenti menjadi senjata rahasia dan berubah menjadi spesifikasi standar.

2. Evolusi Makro di Immortal

Pemisah utama antara Immortal dan Honor/Glory adalah pemahaman Makro yang presisi.

  • Rotasi dan Prioritas Objektif: Kapan berotasi, kapan mengamankan atau merelakan Turtle, Lord, dan Turret.
  • Kontrol Peta: Manajemen tempo gelombang minion (slow push vs hard push) untuk menciptakan tekanan ekonomi.
Faktor Kemenangan Dampak thd Win Rate Fokus Utama
Draft Pick dan Komposisi ~60% Sinergi hero dan Counter-pick
Makro dan Map Awareness ~25% Rotasi dan Prioritas Objektif
Mikro dan Mekanik Motorik ~15% Eksekusi combo dan Waktu respons

Kesimpulan

Mythical Immortal bukan etalase kecepatan jari. Ini ruang lingkup seorang arsitek sistem — kemenangan divalidasi oleh eksekusi draft superior (60%), penguasaan makro yang disiplin, dan mikro hanya sebagai piranti pelengkap.

Evolusi Bot Indodax: Mengatasi "Maintenance Trap" dan Migrasi SQLite

Mengembangkan Market Screener untuk Indodax jauh lebih menantang dari sekadar membaca orderbook. Bot ini kini di versi V11.0 — berevolusi dari skrip pemantau sederhana menjadi sistem berkecepatan tinggi yang ditenagai Global Oracle dan Database Engine.

1. Jebakan "Maintenance Trap"

Sering terjadi anomali di mana harga koin tiba-tiba melonjak secara tidak wajar. Ini adalah jebakan ilusi likuiditas — bursa sedang maintenance, menutup akses deposit, membuat pasokan lokal langka padahal harga globalnya diam di tempat.

Saya mengintegrasikan modul Global Oracle menggunakan library CCXT. Bot mengecek harga wajar di Binance, Gate.io, dan MEXC. Jika harga lokal melonjak lebih dari 15% di atas harga global, bot memblokir sinyal buy dan melabelinya "TRAP". Jika terdiskon di bawah -3%, ditangkap sebagai peluang arbitrase "DISC".

2. Anomali API dan Koin "Meme"

Beberapa token baru (seperti TROLLSOL) terkadang gagal ditarik sistem pembaruan otomatis sehingga bot mengklasifikasikannya sebagai koin lokal. Solusinya: injeksi manual ke struktur Whitelist untuk memastikan perhitungan price gap tetap akurat tanpa bergantung sepenuhnya pada respons API.

3. Perombakan Total: Dari CSV ke SQLite

Pada versi awal, bot mencatat seluruh metrik pasar ke file CSV. Ketika dataset membengkak melewati 60.000 baris, metode ini memicu latency dan risiko memory leak. Solusinya adalah migrasi ke SQLite dengan Write-Ahead Logging (WAL) — bot V11.0 kini mampu menyimpan jutaan data real-time dengan kecepatan tinggi. Dataset ini yang kelak menjadi fondasi pelatihan model Machine Learning.
